## 2. Executive Summary & 10-Dimension Scorecard

`@corgelabs/corge` v2.0.0 establishes a clean, high-cohesion serverless foundation: a flat 11-domain layout with zero nested directories, strict `#private` class encapsulation, non-enumerable `corge.internals`, `AsyncLocalStorage` ambient context (`useCorge()`), monotonic epoch-fenced workflows with GCS Claim-Check offloading, content-addressed `FileRef` storage, multi-surface route projection (REST, Cloud Tasks, AI tools, OpenAI `/v1/chat/completions`, Streamable HTTP MCP), and unified transactional email and billing engines.

Before `@corgelabs/corge` is safe for external or multi-project production adoption, **5 `P0` security/isolation blockers** and **11 `P1` correctness/portability/packaging blockers** must be resolved:

1. **Critical Auth & Billing Privilege Escalations (`P0`)**: Social OIDC sign-in fails open when `CORGE_CONFIG.auth.oauth` is unconfigured (`[P0-1]`, enabling cross-app account takeover from any third-party Google/Apple `id_token`); `POST /api/payments/checkout` and `/charge` allow any regular user to pass custom \$0.50 amounts with injected `metadata: { planId, productId }` that the signed webhook handler trusts to grant paid plans and token packs (`[P0-2]`); and account recovery promotes an unverified `newPrimaryEmail` with `emailVerified: true` (`[P0-3]`, enabling account pre-hijacking).
2. **Cross-Tenant Data Leaks (`P0`)**: Workflow `dedupeKey` / `Idempotency-Key` hashing omits `userId` (`[P0-4]`, returning another tenant's persisted workflow response on key collision), and `AttachmentsService.scan`/`.process` omit service-layer `canAccessFile` checks while reading `file` docs with `bypassRbac: true` (`[P0-5]`).
3. **Standalone Portability, Type Augmentation & Release Readiness (`P1`)**: Hardcoded `/Users/nikdelvin/corgelabs/corge` and `68329189121-compute@developer.gserviceaccount.com` remain in CLI/config (`[P1-4]`); `declare module '@corgelabs/corge' { interface Register }` does not merge into `RegisteredCollections` (`[P1-3]`); `README.md`'s 30-second quickstart fails compilation on 4 API mismatches (`[P1-9]`); `corge init` omits `firebase.json` while `corge deploy` skips rules merging whenever consumer rules exist (`[P1-10]`); and `publish.yml` omits `--provenance` while rebasing/tagging *after* `npm publish` (`[P1-11]`).

- **Pillar**: Pillar 4 & Pillar 5 — Hot-Path Efficiency & Breaker Concurrency
- **Root Cause & Impact**:
  1. Every `acquireLimit` call runs `this.#slots.filter(...)` + `const next = [...this.#slots]`, allocating two `2,000`-element arrays per call on `'firestore'` (`max: 2000`). Since `#slots` is monotonically non-decreasing, advancing a `head` index is $O(1)$ amortized with zero copies.
  2. `acquireHttpLimit` evicts `httpCounters.keys().next().value!` when `size >= 5000` without sweeping expired entries first, allowing spoofed/varied keys to evict active rate-limit counters prematurely.
  3. When `OPEN` expires (`45s`), all concurrent callers entering `circuitBreaker` observe `OPEN` + elapsed `>= 45_000`, transition locally to `HALF_OPEN`, and fire simultaneous upstream probe requests instead of a single gated probe.
- **Proposed Fix**: Sweep expired entries in `httpCounters` before FIFO eviction, cap `breakerCache` (`<= 256`), track a `halfOpenProbeInFlight` `Set<string>` so only 1 caller probes `HALF_OPEN` while peers fail fast/fallback, and prune `#slots` via a binary-search/head-splice check (`if (this.#slots[0] <= cutoff)`).
